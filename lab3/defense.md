# Защита лабораторной 3

## Что сделано

**Мой вариант 3: Open Library Search API + Authors API.**
Поиск книг `python programming`, присоединение сведений первого автора, анализ языков и годов издания.
Основной результат: 360 книг. n8n: 30 книг без отдельного сбора авторов.
API-ключ не нужен.

## 1. Подготовка

В VS Code откройте dataMining, затем Terminal → New Terminal.
Если терминал сейчас в другой лабе, сначала вернитесь в корень проекта.
Команды ниже для этого подготовленного ПК:

~~~powershell
cd lab3
$labPython = (Resolve-Path ..\.lab-runtime\venv\Scripts\python.exe).Path
~~~

На другом ПК установите своё окружение по README. Не копируйте путь к чужому python.exe.

Откройте report.pdf и lab3.ipynb. В блокноте выберите этот Python.
RUN_COLLECTION оставьте False: ячейки покажут сохранённый набор.

## 2. Показать API и заголовки

Откройте collect.py: URL /search.json и параметры q, offset, limit, fields, sort.
В браузере можно открыть https://openlibrary.org/search.json?q=python&limit=1 .

Для настоящего нового запроса и вывода заголовков:

~~~powershell
& $labPython collect.py --show-headers
~~~

Что показать в терминале и headers_example.json:

- GET и URL с параметрами.
- User-Agent: какая программа обращается к API.
- Accept: ожидается JSON.
- Статус 200 при успешном ответе.
- Content-Type: формат ответа.
- RateLimit-* показывать только если сервер их прислал. Их отсутствие нормально.
- Retry-After учитывается при 429; при обычном 200 его может не быть.

Фраза: «Отправляю GET с параметрами поиска. Проверяю статус и формат, затем читаю JSON».

Если сеть сейчас отказывает, покажите сохранённый headers_example.json и сообщите, что это предыдущий ответ. Не называйте его новым запуском.

## 3. Пагинация, повторы и авторы

В collect.py найдите paginate и get_json.
Четыре порции по 90: offset 0, 90, 180, 270.
Пауза 1,1 с, timeout 20 с; 429 и 5xx повторяются максимум дважды после первой попытки.
Покажите collection_log.csv и authors_cache.json.

Фраза: «Один ответ не содержит весь набор. Offset сдвигается на размер полученной порции. Авторов запрашиваю по ключу и кэширую».

Выполните ячейки lab3.ipynb сверху вниз при RUN_COLLECTION = False.

## 5. Короткий повторный сбор

Чтобы сохранить исходную выборку отчёта, сделайте отдельную папку с копией состояния:

~~~powershell
$demoDir = "demo_" + [guid]::NewGuid().ToString("N").Substring(0,8)
New-Item -ItemType Directory -Path $demoDir | Out-Null
Copy-Item -LiteralPath data_raw.jsonl,state.json,authors_cache.json -Destination $demoDir
& $labPython collect.py --output $demoDir --run-label demo
~~~

Смотрите new_records и число запросов в metrics_demo.json внутри новой папки.
Раньше повтор дал ноль новых ключей; API может измениться, поэтому обещать ноль заранее нельзя.
Полный новый сбор с авторами занимает несколько минут и для короткого показа не нужен.

## 6. Показать n8n

Откройте http://localhost:5679 и workflow «Lab 3 Open Library REST API».
Если его нет: меню workflow → Import from File → lab3/nocode/workflow.json.
При импорте проверьте абсолютные пути Save CSV / Save error log к lab3/nocode.
Готовая локальная установка n8n уже настроена; не создавайте второй профиль.

1. Fetch books: GET, параметры, три порции по 10, интервал 1,1 с.
2. Check books response: проверка ответа и ветка ошибки.
3. Transform fields: названия полей и числовые типы.
4. Daily schedule: ежедневное расписание.
5. Execute workflow. Дождитесь зелёных узлов.
6. Откройте выход Transform fields / CSV: 30 строк.
7. Откройте nocode/nocode_result.csv.

Фраза: «Это уменьшенный сбор без Authors API. С Python сравниваю пять общих полей; все 30 строк совпали».

## 7. Завершение и частые вопросы

Покажите таблицу сравнения в отчёте.
Нельзя сравнивать только полное время 360 книг с авторами и 30 книг без авторов: объём разный.

- JSONL хранит исходные записи; CSV удобен для таблицы.
- Кэш уменьшает запросы к авторам; известные ключи не добавляются второй раз.
- Годы и языки характеризуют эту выборку, а не весь каталог.
- Публичное имя автора может быть персональными данными; контакты и биографии здесь не нужны.

Дополнительно покажите outliers.json: 11 необычных лет и 50 значений edition_count по IQR; строки сохранены, потому что бизнес-правила не нарушены.
