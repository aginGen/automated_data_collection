## Установка

Нужен Python 3.10+. Команды выполняются из папки лабораторной. Окружение размещается в соседнем техническом каталоге:

```powershell
python -m venv ..\.lab-runtime\lab4-python
..\.lab-runtime\lab4-python\Scripts\python.exe -m pip install -r requirements.txt
..\.lab-runtime\lab4-python\Scripts\python.exe -m playwright install chromium
```

Откройте ноутбук в VS Code / Jupyter, выберите это окружение и выполните ячейки сверху вниз. По умолчанию показываются сохранённые результаты и выполняются проверки CSV. Обращения к сайту отключены. Метрики, параметры измерений и результаты автономных проверок хранятся внутри самого ноутбука.

## Повтор сбора и проверок

В ячейке **«Локальный rendering API и запуск»** находятся флаги:

| Флаг | Действие |
|---|---|
| `RUN_COLLECTION = True` | Повторить диагностику, браузерный сбор, HTTP-сбор, сверку и замер блокировки медиа |
| `RUN_RESILIENCE_CHECKS = True` | Выполнить автономные проверки предохранителей, редизайна и smoke-check |
| `RUN_N8N = True` | Исторический режим ноутбука для n8n; для переносимого workflow используйте launcher ниже |
| `RUN_N8N_ERROR_CHECK = True` | Проверить ветку ошибки rendering API |
| `START_N8N_EDITOR = True` | Исторический режим редактора ноутбука; для переносимого workflow используйте launcher ниже |
| `STOP_SERVICES = True` | Завершить сервисы, запущенные этим ноутбуком |

Флаги ноутбука, относящиеся к n8n, описывают прежнюю схему запуска; для текущих переносимых JSON используйте launcher из раздела n8n ниже. После изменения нужного флага выполните эту ячейку повторно. Для следующего обычного просмотра верните флаги в `False`. Новый браузерный и HTTP-срез, дополнительные журналы и измерения появятся во временной папке, путь которой напечатает ноутбук. Сохранённые основные CSV при таком сборе не перезаписываются. Сохранённый исторический результат n8n находится в `nocode/nocode_result.csv`; для нового перенесённого workflow используйте launcher из раздела n8n ниже.

Браузер выполняет максимум 24 прокрутки, останавливается после двух итераций без новых ключей или при достижении лимита 200 товаров. Пауза между взаимодействиями — не меньше 1 с. Ответы данных ожидаются через `expect_response` и `wait_for_function`. Порции перекрываются: при шаге offset=10 сервер возвращает до 12 карточек. Поэтому в конце DOM содержит 187 карточек, а CSV — 147 уникальных товаров.

Для отдельной демонстрации таймаута после вызова `work = prepare_runtime()` можно выполнить в ячейке:

```python
result = subprocess.run(
    [sys.executable, "-X", "utf8", str(work / "collect.py"), "demo-timeout",
     "--out", str(work / "timeout-demo")],
    cwd=LAB_ROOT,
)
assert result.returncode == 2
```

Код 0 означает успех, 1 — фатальную ошибку, 2 — специально вызванный таймаут. Исходники всех временных скриптов находятся в ячейках ноутбука. Запускайте сетевые сценарии последовательно. При изменении каталога обновляйте и сверяйте все три набора.

## n8n

Из папки этой лабораторной запустите соседний переносимый комплект (Python 3.10+ и Node.js 22 в PATH):

```powershell
python ..\n8n_portable\launch.py --setup --browser
python ..\n8n_portable\launch.py --port 5679
```

Первая команда устанавливает зависимости; при последующих запусках достаточно второй. Launcher задаёт рабочий каталог n8n равным корню комплекта `n8n_portable`, создаёт `outputs/lab3`–`outputs/lab7` и запускает локальные вспомогательные сервисы ЛР4 и ЛР5. Откройте `http://127.0.0.1:5679`, импортируйте `nocode/workflow.json` этой лабораторной или соответствующий `../n8n_portable/workflows/labN.json` и выполните **Manual start**. Все относительные пути файлов в workflow отсчитываются от корня комплекта, а не от папки лабораторной. При запуске n8n из другой директории без launcher нужно самостоятельно установить рабочий каталог и создать папки. Расписание в экспорте выключено.

Для этой работы launcher поднимает rendering API на `127.0.0.1:8894`. Он исполняет JavaScript и прокручивает учебную страницу; n8n получает DOM и извлекает карточки. Результат нового запуска — `../n8n_portable/outputs/lab4/nocode_result.csv`, журнал — `outputs/lab4/error_log.csv`. [nocode_result.csv](nocode/nocode_result.csv) — сохранённый исторический результат. Workflow неактивен; расписание настроено на 08:00 Asia/Yekaterinburg. Ошибочная ветка записывает журнал и завершает выполнение ошибкой.
