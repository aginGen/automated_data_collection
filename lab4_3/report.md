Проверить динамическую подгрузку товаров на ScrapingCourse Infinite Scrolling, собрать каталог через Playwright и найденный XHR, сравнить затраты и собрать тот же полный каталог в n8n. По таблице вариантов для группы ПМИ-2-2025: (26 mod 6) + 1 = 3.

**Ограничение объёма.** Собран весь доступный каталог: 147 уникальных товаров. Последние карточки получены при offset=140, далее сервер возвращает 204. Требование ≥200 записей не выполнено из-за конечного размера источника. По образцу предоставленной работы Елисея Глухова ограничение описано явно; товары не размножались повторными обходами. Выполнено 17 циклов прокрутки, что превышает требуемые пять. Расширение на другой источник без согласования не выполнялось [9].

## 3. Схема реализации

Браузерный путь: Chromium → context → page → прокрутка #end-of-page → expect_response → wait_for_function → eval_on_selector_all → нормализация → CSV. Контекст задаёт User-Agent учебного сборщика, viewport 1280×800, locale en-US; таймауты действий 12 с, навигации 35 с. Context и browser закрываются в finally, Playwright — менеджером with [1–3].

Дешёвый путь: requests.Session → тот же HTML-XHR → BeautifulSoup → общая нормализация. Использованы начальная страница и смещения 0…160 с шагом 10, timeout=(10, 30), интервал не меньше 1 с. Для 429/5xx предусмотрены максимум три попытки, backoff, jitter и Retry-After; остальные HTTP-ошибки завершают сбор. Здесь XHR возвращает HTML, поэтому json.loads для данных товаров неприменим.

## 4. Локаторы и устойчивость к редизайну

| Использованный локатор | Назначение и обоснование |
|---|---|
| [data-testid='product-grid'] | Сетка товаров; устойчивый data-атрибут, есть в исходном HTML |
| #end-of-page | Область наблюдения IntersectionObserver; ID не зависит от подписи и языка |
| .product-item .product-name | Название внутри семантического контейнера; нет зависимости от номера div |
| .product-item .product-price | Цена; descendant-селектор переносит дополнительные обёртки |
| item.get_by_role('link') | Адрес товара в поэлементном замере; роль имеет приоритет перед структурным CSS |

В массовом извлечении применяются те же семантические признаки через DOM API. XPath и сгенерированные классы не используются. У карточек названия и цены нет собственных подходящих role/label/data-атрибутов, поэтому применены семантические классы с проверкой полноты [2].

Для трёх локаторов проверены последствия изменений:

| Локатор | Переименование CSS-класса | Дополнительный div | Перевод текста кнопки/подписи |
|---|---|---|---|
| [data-testid='product-grid'] | Не влияет | Не влияет | Не влияет |
| #end-of-page | Не влияет | Не влияет | Не влияет; текст не используется |
| .product-item .product-name | Пустое название или потеря контейнера | Descendant сохраняет поиск | Не влияет; имя товара — данные |

Если владелец переименует ID/data-атрибуты, первые два локатора тоже потребуют обновления. Для названия предпочтителен стабильный data-testid, если площадка его предоставит; придумывать отсутствующий атрибут нельзя. Для контейнера возможна опора на ссылки с href, начинающимся с /ecommerce/product/, с последующей проверкой связи названия и цены.

## 5. Взаимодействие и диагностируемость

После начальных 12 товаров выполняется реальная прокрутка. Сначала страница возвращается наверх, затем #end-of-page прокручивается в область видимости. expect_response ожидает /ajax/products, а wait_for_function подтверждает прирост DOM. time.sleep(1) используется только для вежливой паузы. Порции содержат до 12 карточек при шаге offset=10; начальная порция также повторяется. В финальном DOM 187 карточек, после удаления повторов остаются 147 ключей.

Три предохранителя: максимум 24 итерации; остановка после двух итераций без новых ключей; лимит 200 товаров. Фактически сработало отсутствие прироста: итерация 16 получила 204, на 17-й нового XHR уже не было. Последний таймаут зарегистрирован, сохранены HTML, PNG и сообщение; завершение распознано как исчерпание каталога. Некорректная карточка попадает в item_errors.json, остальные обрабатываются дальше; пустых ошибочных карточек в срезе нет.

collection_log.csv содержит номер итерации, число DOM-карточек, прирост уникальных ключей, итог, длительность, UTC-время, URL, статус и ошибку. Контролируемое ожидание отсутствующего элемента создаёт artifacts/controlled_timeout.* и возвращает код 2. Успех основного CLI — 0, фатальная ошибка — 1. Автономные проверки, включённые в ноутбук, подтвердили предохранители, артефакты, устойчивость к обёртке и переводу, обнаружение смены класса, smoke-check, сохранение точки с запятой в slug и нормализацию пробелов: десять проверок пройдены.

Условия: Windows, Python 3.10, Playwright 1.58.0, Chromium 145, локальный n8n 1.121.3. Это по одному финальному прогону каждого режима. Трафик — сжатые тела завершённых ответов: request.sizes().responseBodySize в браузере и длина undecoded raw body в HTTP. Заголовки, TCP/TLS и локальная передача HTML не включены; 1 МБ = 1 000 000 байт. Браузер учитывает зависимости страницы и сторонние ответы, HTTP — только целевые HTML. Запросы robots.txt относятся к подготовке. Память — сумма RSS Python и дочерних процессов; для n8n добавлены его процессы и rendering API с Chromium, опрос 50 мс. В обоих режимах уже блокировались запрещённые robots.txt товарные изображения. Для 187 DOM-карточек медиана трёх массовых извлечений — 0.007567 с, поэлементных — 1.334374 с, выигрыш 176.3 раза; значения трёх полей совпали. Это микрозамер, не ускорение всей сети.

## 8. No-code реализация

Схема: Manual start / Daily schedule → Render JS → Extract cards → Split cards → Extract fields → Normalize and deduplicate → CSV → Save CSV. Локальный rendering API, код которого включён в lab4.ipynb, исполняет JS в Chromium, ждёт селектор и прокручивает страницу. n8n получает DOM по HTTP, извлекает поля узлами HTML, разворачивает карточки и нормализует записи [4–6].

POST /render передаёт render_js=true, wait_for=[data-testid='product-grid'] .product-item, max_items=200. Сервис слушает только 127.0.0.1:8894 и принимает учебный URL. За один прогон выполнены 1 JS-рендеринг, 17 циклов прокрутки и 26 завершённых запросов к сайтам. После исчерпания каталога из 187 DOM-карточек получены 147 уникальных товаров. Все ключи, названия, цены, валюты и URL совпали с обоими основными CSV. Проверка отклоняет неполный набор. Параметры и сводные результаты измеренного прогона сохранены в ноутбуке. Скриншоты n8n обновлены в изолированном экземпляре по сохранённому HTML `artifacts/nocode_rendered.html`, который локальный тестовый сервер вернул с контрольным числом 147. Повторного обращения к сайту для этих снимков не было.

Ветка HTTP-ошибки: Error details → Error CSV → Save error CSV → Fail execution. Проверка отсутствующего локального маршрута записала журнал ошибки и завершила workflow с ошибкой; CLI вернул 1. Расписание 08:00 Asia/Yekaterinburg настроено, workflow оставлен неактивным. Локальный rendering API и n8n не требуют платы провайдеру; оборудование, электричество и труд не оценены. В этом прогоне один рендер дал 147 товаров. Если другой разрешённый источник позволяет ту же порцию, для 10 000 записей потребуется минимум ceil(10000/147)=69 рендеров; при цене C за рендер это 69C, или 0,0069C на запись. Это расчётная модель, текущий каталог конечен.

## 9. Выводы и рекомендации

Для разового исследования рекомендую HTML-XHR после диагностики: он дал тот же набор и в этом замере оказался в 1.45 раза быстрее браузера. Playwright полезен для разведки и проверки поведения прокрутки; n8n удобен, когда требуется визуальная схема и расписание.

Для ежедневного сбора 10 000 записей на площадке соответствующего объёма предпочтительны разрешённый API или выгрузка, кэш, ограничение частоты и повторы. Перед ростом нагрузки следует проверить условия владельца. Для сайта с антибот-защитой нужны разрешение или официальный интерфейс; при CAPTCHA сбор останавливается. Обход защиты не является рекомендацией лабораторной.

## 10. Правовая и этическая оценка

Сбор выполнен на учебном стенде. Сохранённое в ноутбуке содержимое robots.txt обоих имён хоста включает Disallow: /ecommerce/*; этот wildcard учтён отдельно, так как стандартный urllib.robotparser его не реализует. Адреса товаров сохраняются как идентификаторы и не открываются; соответствующие изображения блокируются. Рабочие пути /infinite-scrolling и /ajax/products правилом не запрещены. Сбор последовательный, пауза 1 с; вход в реальные аккаунты и обход CAPTCHA отсутствуют. Robots.txt регулирует автоматический доступ, но не предоставляет лицензию на любое использование материалов [7].

Набор включает учебные названия, цены, валюту, URL и время сбора; полей, позволяющих определить физическое лицо, в нём нет. В этой обработке товарного каталога не установлено предмета применения 152-ФЗ к данным товаров; фамилия студента в оформлении — отдельные персональные сведения. Публичность сайта сама по себе не исключала бы действие закона при появлении сведений о людях. Контакты пользователей, аккаунты и изображения не включены [8].
