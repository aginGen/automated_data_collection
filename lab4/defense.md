# Защита лабораторной 4

## Что сделано

**Мой вариант 3: бесконечная прокрутка ScrapingCourse.**
На назначенном сайте найдено 147 товаров. Для минимума 200 добавлен дополнительный ScrapingSandbox с 200 товарами.
Итого 347. Сравниваются обычный браузер и сбор с меньшим числом загрузок.

## 1. Подготовка

Откройте новый терминал в корне dataMining:

~~~powershell
cd lab4
$labPython = (Resolve-Path ..\.lab-runtime\venv\Scripts\python.exe).Path
~~~

Откройте report.pdf, lab4.ipynb и collect.py.
Блокнот по умолчанию читает сохранённые результаты; RUN_COLLECTION = False.
Для сборки на другом ПК сначала выполните установку и playwright install chromium по README.

## 2. Объяснить, почему нужен браузер

В обычном браузере откройте https://www.scrapingcourse.com/infinite-scrolling .
Прокрутите вниз: карточки догружаются.

Откройте в браузере F12 → Network → Fetch/XHR, включите Preserve log и прокрутите снова.
Покажите запрос /ajax/products и его страницу/порцию. Название запроса видно в сохранённом collection_log.csv.
У ScrapingSandbox отдельный полный XHR-источник в этой проверке не найден; там остаётся облегчённый браузер.

Можно повторить диагностику:

~~~powershell
& $labPython collect.py --mode diagnose
~~~

В artifacts/diagnostics.json: в исходном HTML 12 и 20 карточек.
Без JavaScript прокрутка не увеличивает эти числа.
Фраза: «HTTP получает только первоначальную разметку. Остальные товары добавляет JavaScript».

## 3. Показать браузерный сбор

В collect.py найдите scroll_collect, wait_for_function, eval_on_selector_all и route.
Если название функции отличается, ищите указанные вызовы.

- Локаторы выбирают карточки и поля по классам.
- Прокрутка ждёт увеличения числа карточек, а не только фиксированного sleep.
- Остановка: нет роста, достигнут предел или вышел общий бюджет.
- eval_on_selector_all извлекает все карточки одной операцией.
- Изображения, шрифты и медиа можно не скачивать.
- При сбое сохраняются HTML и скриншот.

При необходимости запустите весь сбор (обычно около минуты, зависит от сайтов):

~~~powershell
& $labPython collect.py --mode all
~~~

Команда обновит результаты этой лабы. Для короткой защиты достаточно сохранённого запуска и диагностики.

## 4. Результаты и сравнение

Выполните ячейки lab4.ipynb сверху вниз.
Покажите data_browser.csv, data_light.csv и comparison.json.
Ожидается по 347 строк и совпадение ключей, названий, цен и URL.

Откройте metrics_browser.json и metrics_light.json.
В отчёте сохранены замеры около 57 и 27 с; новый запуск может дать другое время.
Облегчённый путь: XHR у ScrapingCourse; браузер без тяжёлых ресурсов у Sandbox.
Не говорите, что оба источника собраны без браузера.

Фраза: «Проверяю одинаковый результат. Потом сравниваю время и объём ответов, а не только скорость».

## 5. n8n и рендерер

В отдельном терминале из lab4 запустите:

~~~powershell
$labPython = (Resolve-Path ..\.lab-runtime\venv\Scripts\python.exe).Path
& $labPython render_api.py --port 8789
~~~

Оставьте окно открытым.
Рендерер сам запускает браузер, прокручивает страницу и отдаёт готовый HTML.
Это Python-сервис перед n8n; n8n сам JavaScript страницы не выполняет.

Откройте http://localhost:5679 и workflow «Lab 4 Dynamic products via rendering API».
При необходимости импортируйте lab4/nocode/workflow.json.
Проверьте абсолютные пути Save CSV / Save error log.

1. Render page with JS: URL http://127.0.0.1:8789/render .
2. Check rendered HTML: проверка ответа.
3. Узел извлечения HTML: правила поиска полей.
4. Daily schedule: расписание.
5. Execute workflow.
6. Откройте результат и nocode/nocode_result.csv: 30 товаров.

Если ECONNREFUSED на 8789 - сначала запустите render_api.py.
Если 5679 не открывается - нужен запущенный n8n.
