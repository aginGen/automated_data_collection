# Лабораторная работа № 3. Сбор данных через REST API: код и no-code

**ПМИ-2-2025. Вариант 3.**

## 1. Цель и вариант

Получить книги по теме `python programming` через Open Library Search, дополнить сведениями Open Library Authors и сравнить Python со сценарием n8n. Основной срез Python содержит 360 книг с четырёх страниц поиска и сведения первого автора. В отдельном замере Search-only Python и n8n получили по 360 записей. API может вернуть другой состав и длительность при следующем запуске.

## 2. Паспорт API

| Параметр | Основной источник: Search | Обогащение: Authors |
|---|---|---|
| Название и базовый URL | Open Library Search; `https://openlibrary.org` | Open Library Authors; тот же домен |
| Версия | Номер в URL не указан | Номер в URL не указан |
| Эндпоинт, метод, ответ | `GET /search.json`, JSON с `docs` и `numFound` | `GET /authors/{ID}.json`, JSON автора |
| Авторизация | Публичное чтение без ключа | Публичное чтение без ключа |
| Параметры | `q`, `limit`, `offset`, `fields`, `sort=key` | Идентификатор автора в пути |
| Пагинация | `offset/limit`; API также поддерживает `page/limit`, указанные в ТЗ | Для одного автора не нужна |
| Документированная квота | По умолчанию 1 запрос/с; 3 запроса/с для приложения с контактом в User-Agent | Общая квота того же API |
| Квота в пересчёте на минуту | 60 или 180 запросов/мин соответственно; это пересчёт, а не отдельная минутная квота | Та же |
| Заголовки | Запрос: User-Agent, Accept; ответ: Content-Type; Retry-After и RateLimit-* учитываются при наличии | Те же проверки |
| Заголовки квоты в сохранённом примере | Не получены; отсутствие не означает отсутствие лимита | В журнале лимитных заголовков нет |
| Даты | `first_publish_year` — целый год; время сбора — UTC ISO 8601 | `last_modified.value` приводится к UTC |
| Уникальный ключ | `key` вида `/works/OL…W`, в CSV — `work_id` | `author_key` вида `OL…A` |
| Потенциальные персональные сведения | Имена авторов | Имя; контакты и биографии не сохраняются |
| Условия | Кэш, ограничение нагрузки; для массовых данных рекомендуются выгрузки каталога | Не использовать для массового обхода авторов |

Источники контракта: [Search](https://openlibrary.org/dev/docs/api/search), [Authors](https://openlibrary.org/dev/docs/api/authors), [правила API](https://openlibrary.org/developers/api). В коде User-Agent содержит имя приложения, но не контакт; используется обычный лимит. Для регулярного использования следует добавить собственный контакт и соблюдать правила сервиса.

## 3. Архитектура и решения по сбору

**Search + Authors → requests.Session → нормализация и merge → проверки → JSONL, CSV, log, state.**

Сбор и пагинация реализованы в `lab3.ipynb`: четыре порции по 90 книг со смещениями 0, 90, 180 и 270. Следующее смещение вычисляется по фактической длине ответа. Пределы задаются параметрами `page_size`, `max_records` и `max_pages`; сбор прекращается при пустой странице, достижении `numFound` или заданного лимита. Результаты сортируются по ключу; изменения каталога могут сдвинуть страницы.

Между началами запросов задан интервал 1,1 с; `timeout=20`. Requests ограничивает ожидание соединения/чтения, а не полное время всех повторов. Проверяются статус, Content-Type и JSON. Диагностика ошибки содержит первые 200 байт тела. Только 429 и 5xx повторяются максимум дважды после первой попытки: экспоненциальная задержка, случайная добавка и ожидание не меньше Retry-After. Остальные 4xx и сетевые ошибки завершают сбор с записью журнала.

`pandas.json_normalize(sep='_')` раскрывает JSON. Массив языков разворачивается через `record_path` и `meta` в отдельную таблицу. Сведения первого автора присоединяются по ключу с `validate='many_to_one'`: 360 книг до и после, 357 совпадений; запрошено 306 уникальных авторов. Сохраняется и общее число авторов, но обогащение выполняется только для первого.

`data_raw.jsonl` содержит записи Search до нормализации и время сбора; это не побайтовая копия HTTP-ответов. Кэш сведений Authors сохраняется в метаданных ноутбука. `collection_log.csv` содержит страницу, параметры, статус, число записей, длительность, время UTC, номер попытки и ошибку.

При повторе сканируется то же ограниченное окно, неизвестные ключи добавляются, существующие записи не обновляются. `state.json` содержит известные ключи и watermark завершённого просмотра; это не `updated_since` и не курсор API. Архивный повтор дал 0 новых строк и четыре запроса благодаря кэшу авторов. Производные таблицы пересоздаются и при нуле новых записей. После незавершённой записи raw повтор восстанавливает таблицы, проверяя принадлежность поисковому запросу. Полнота обновлений вне окна не гарантируется.

## 5. Сценарий n8n

Manual start / Daily schedule → Fetch books → Check books response → Split records → Transform fields → CSV → Save CSV. Расписание задано на 08:00 `Asia/Yekaterinburg`; для измеренного запуска использован ручной триггер. HTTP Request получил четыре страницы по 90 записей (offset 0, 90, 180, 270); между ответом одной страницы и запросом следующей выдерживалась пауза 1,1 с, таймаут — 25 с. Параметры поиска и семь запрошенных полей совпадают с парным Python Search-only замером. На выходе пять полей: `work_id`, `title`, `first_publish_year`, `edition_count`, `url`. Authors API не вызывается.

Ошибки направляются по отдельной ветке workflow. `nocode/nocode_result.csv` содержит 360 уникальных строк; все пять выходных полей совпадают по значениям и порядку с результатом Python Search-only. Приложенные снимки workflow и результата относятся к архивному запуску на 30 записях; текущий CSV содержит 360 строк. Экспорт: [workflow.json](nocode/workflow.json); [результат](nocode/nocode_result.csv).

*120 и 60 минут — ориентировочная оценка; автоматический хронометраж полной разработки не проводился. Search-only замер включает Search API и запись CSV, но не Authors API, установку n8n или запуск процессов. Использованы одинаковые параметры; это одна пара запусков, поэтому сеть и кэш могут повлиять на результат. Полный Python сбор с Authors приведён отдельно: 360 книг, 310 запросов, 348,8125 с в сохранённом срезе и 383,0805 с в свежем запуске.

**Используются бесплатное чтение API и локальный n8n без облачной подписки; электричество, оборудование и труд не оценены. Это расчёт платы сервисам, а не полная стоимость владения и не разрешение на 100 массовых выгрузок. Кэш и допустимая нагрузка всё равно обязательны.

В Python реализованы обогащение, контроль качества и анализ; в n8n настроены сбор тех же 360 книг, расписание и выгрузка CSV. Один замер не позволяет заключить, что один инструмент всегда быстрее другого. Предлагаемый гибрид: n8n запускает Python по расписанию и обрабатывает результат; такой гибрид в работе не реализован.

## 7. Правовая и этическая оценка

**Проверка 31.10.2026.** На эту дату [robots.txt Open Library](https://openlibrary.org/robots.txt) вернул HTTP 200 и содержит `Disallow: /search`; проверка `urllib.robotparser` для User-Agent `university-data-collection-labs/1.0` запретила `/search.json`, а выбранный `/works/...json` разрешила. Поэтому новые Search-сборы этим Python-клиентом блокируются; таблицы и показатели выше относятся к ранее сохранённому опыту и не пересчитывались. Теперь клиент проверяет robots.txt для каждого origin до целевого запроса: 404 трактуется как отсутствие файла, не-200/404, перенаправление или сетевая ошибка — как запрет до выяснения. Служебный запрос robots.txt не входит в счётчик и журнал целевых HTTP-попыток. В сценарий n8n добавлена отдельная проверка robots.txt перед поиском, с тем же запретом целевого запроса при отказе или невозможности проверки. Права на данные и условия API проверяются отдельно от robots.txt.

Собираются метаданные, тексты и обложки книг не загружаются. Open Library просит предоставлять вклады в каталог по CC0 и отдельно оговаривает возможные права на материалы; условия нельзя автоматически переносить на тексты книг. При росте объёма нужны выгрузки каталога вместо обхода сотен ресурсов. Источники: [использование данных](https://openlibrary.org/help/faq/using), [лицензирование](https://openlibrary.org/developers/licensing), [правила API](https://openlibrary.org/developers/api).

Имена авторов могут относиться к персональным данным. Публичный API не даёт универсального согласия на распространение. В учебном анализе рассматриваются п. 8 ч. 1 ст. 6 152-ФЗ для научной деятельности при соблюдении прав субъекта и п. 9 для исследовательской/статистической обработки с обязательным обезличиванием. Текущий CSV с именами не является обезличенным; это ограничение нельзя снять одной ссылкой на закон. Контакты и биографии исключены. Предлагаемый срок хранения учебных копий — до проверки работы и не дольше 30 дней после неё; публичные выводы можно хранить в агрегатах. Git-история и сторонние копии требуют отдельного удаления, удаление локального файла их не очищает. Основание и условия: [официальный текст 152-ФЗ, статьи 6 и 21](https://mintrud.gov.ru/docs/laws/130).
