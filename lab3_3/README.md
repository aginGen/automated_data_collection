# Лабораторная 3. REST API: Python и n8n

ПМИ-2-2025, вариант 3: Open Library Search + Authors. Python собирает 360 книг по запросу `python programming` и обогащает их сведениями первого автора. Сценарий n8n получает 360 строк только из Search API.

## Запуск ноутбука

Нужны Python 3.10+ и Node.js 22. В PowerShell откройте папку `lab3_3` и создайте окружение:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Откройте [lab3.ipynb](lab3.ipynb) в VS Code или Jupyter и выполните ячейки сверху вниз. По умолчанию ноутбук показывает сохранённые данные без доступа к сети и перезаписи файлов. Для нового сбора включите `RUN_COLLECTION = True`: результат появится во временной папке. `RUN_REPEAT = True` дополнительно запускает проверку повторной загрузки.

Сохранённая таблица книг находится в [data_clean.csv](data_clean.csv), исходные записи поиска — в [data_raw.jsonl](data_raw.jsonl), журнал — в [collection_log.csv](collection_log.csv), состояние — в [state.json](state.json). Код сбора, сведения авторов, проверки качества, графики и сравнение инструментов находятся в ноутбуке.

## n8n

Установите локальный runtime и запустите n8n из PowerShell в папке проекта:

```powershell
npm.cmd install --prefix ..\.lab-runtime n8n@1.121.3
$env:N8N_USER_FOLDER = Join-Path $PWD '..\.lab-runtime\user'
$env:N8N_LISTEN_ADDRESS = '127.0.0.1'
$env:N8N_PORT = '5679'
node ..\.lab-runtime\node_modules\n8n\bin\n8n start
```

Откройте `http://127.0.0.1:5679`, импортируйте [workflow.json](nocode/workflow.json) и укажите абсолютные пути в узлах **Save CSV** и **Save error log**. Для основной выгрузки используйте `nocode\nocode_result.csv`; журнал ошибки можно сохранить во временный каталог вне папки сдачи. Нажмите **Execute workflow**.

Файл [nocode_result.csv](nocode/nocode_result.csv) содержит текущие 360 строк. Снимки [workflow](nocode/screenshot_workflow_30.png) и [результата](nocode/screenshot_result_30.png) относятся к прежней версии на 30 строк.

## Термины

| Термин | Простое объяснение |
|---|---|
| REST API | Интерфейс, через который программа получает данные по HTTP. |
| Endpoint | Адрес конкретного ресурса, например `/search.json`. |
| GET | HTTP-запрос для чтения данных. |
| Параметры запроса | Значения после `?`, например `q`, `limit` и `offset`. |
| Пагинация | Получение результатов частями; здесь по 90 книг за страницу. |
| HTTP status | Код результата: 200 — запрос выполнен, 4xx — проблема запроса, 5xx — ошибка сервера. |
| Rate limit | Ограничение частоты запросов к API. |
| JSON | Формат ответа API с полями и вложенными списками. |
| JSONL | Текстовый файл, где каждая строка — отдельный JSON-объект. |
| CSV | Таблица, сохранённая в строках и столбцах. |
| Session | Объект Python `requests.Session`, повторно использующий настройки соединения и заголовки. |
| Timeout | Предел ожидания ответа, после которого запрос завершается ошибкой. |
| Нормализация | Преобразование вложенного JSON в табличные столбцы и строки. |
| Обогащение | Добавление к записи сведений из другого источника; здесь — полей первого автора. |
| Кэш | Повторное использование ранее полученных данных; ответы Authors сохранены в ноутбуке. |
| Nullable `Int64` | Целочисленный тип pandas, который допускает пропущенное значение. |
| `many_to_one` | Проверка merge: нескольким книгам может соответствовать одна запись автора. |
| IQR | Межквартильный размах; правило для поиска необычных значений. |
| Watermark | Отметка состояния, помогающая не добавлять уже известные ключи повторно. |

## Право и использование данных

Собираются библиографические метаданные; тексты и обложки не скачиваются. Имя автора может относиться к персональным данным. Оценка оснований и срока хранения приведена в [report.md](report.md).
