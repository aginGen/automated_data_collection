## 1. Цель и вариант

Разработать Scrapy-проект с обходом «список цитат → страница автора», четырьмя звеньями Item Pipeline, SQLite, возобновлением и HTTP-кэшем; сравнить его с n8n на одинаковых 30 цитатах. В Excel назначен вариант 3: `quotes.toscrape.com`.

Получены все 100 уникальных цитат с десяти страниц и сведения 50 авторов. Дополнительно выполнен обход тегов по подходу [LaintAge/web-scrapers](https://github.com/LaintAge/web-scrapers/tree/main/lb5): сохранены 190 связей «цитата–тег». Они относятся к 69 цитатам и не являются 190 новыми цитатами. Общий минимум ТЗ в 300 уникальных записей цитат на этом каталоге не достигнут: источник содержит 100; страница 11 пуста. Значение `CLOSESPIDER_ITEMCOUNT=300` задаёт предел, а не гарантирует объём.

## 2. Карта источника и ключи

Основная точка входа — `https://quotes.toscrape.com/`; список содержит `.quote`, текст `span.text`, имя `small.author`, теги `.tags a.tag`, ссылку на автора и `li.next a`. На втором уровне извлекаются `.author-born-date`, `.author-born-location`, `.author-description`. Ссылки приводятся к URL с завершающей `/`, чтобы не создавать лишних HTTP 308.

Дополнительный путь: десять популярных тегов главной → страницы тегов с пагинацией → новые теги внутри цитат → авторы. Он охватывает связанный с начальными тегами участок каталога. Ключ цитаты — SHA-256 от нормализованного имени автора в нижнем регистре, LF и текста цитаты. Регистр текста сохраняется. Ключ связи — пара `(business_key, source_tag)`; URL ключом записи не служит.

## 3. Архитектура и пауки

Проект создан через `scrapy startproject quotes_crawler`. Engine связывает компоненты; Scheduler хранит очередь и фильтрует повторные запросы; Downloader получает HTTP; Spider извлекает поля; Item Pipeline проверяет и сохраняет записи. Feed Exports формирует JSONL, Stats Collector собирает счётчики, HTTP Cache воспроизводит ответы, SpiderState и JOBDIR сохраняют состояние.

Использованы обычные `Spider`: `quotes` для десяти страниц и `tags` для графа тегов. Явные `parse` и `parse_item` удобны для разных схем списка и карточки; правила CrawlSpider здесь усложнили бы передачу контекста. Пагинация выполняется через `response.follow`, контекст — через `cb_kwargs`; ожидающие цитаты одного автора объединяются. Автор скачивается один раз за прогон, его сведения сохраняются в состоянии. Селекторы используют классы и атрибуты, индексных XPath нет. Проверки `.get()` и адресов тегов пропускают повреждённые ссылки без исключения, увеличивая `tag/invalid_url`; `errback` учитывает `errors/request` и затронутые цитаты.

## 4. Item Pipeline

| Приоритет | Обработка и счётчики |
|---|---|
| 100 | Проверка обязательных полей, включая строки из пробелов; `DropItem`, `dropped/missing_fields` |
| 200 | Пробелы, нижний регистр тегов, дата ISO, номер страницы int, бизнес-ключ; `dropped/invalid_value`, `quality/empty_tags` |
| 300 | Дедупликация цитат по автору и тексту, связей по цитате и тегу; `dropped/duplicate` / `dropped/duplicate_relation` |
| 400 | Одно соединение в open/close, `executemany` пакетами по 20; остаток записывается при закрытии; `database/rows_written` / `database/relations_written` |

SQLite содержит `quotes` и `quote_tags`. Основной пайплайн обновляет цитаты через INSERT OR REPLACE; теговый добавляет связь и использует INSERT OR IGNORE для уже известных цитат, сохраняя исходную страницу и время основного сбора. Соединение внутри `process_item` не открывается. Счётчики связей разделены на попытки, реальные вставки и пропуски: `relations_attempted`, `relations_written`, `relations_ignored` в группе `database/`. Повтор 190 связей дал 0 вставок и 190 пропусков (`data/replay_relations.json`); это проверка пайплайна без сети. Пробельные поля, неправильные типы, даты и ссылки покрыты регрессионными тестами.

## 5. Настройки и ограничение нагрузки

| Настройка | Значение и причина |
|---|---|
| ROBOTSTXT_OBEY / USER_AGENT | True; PGU-DataMining-Lab5 с указанием учебного назначения |
| CONCURRENT_REQUESTS / PER_DOMAIN | 4 / 2; ограничение одновременной нагрузки |
| DOWNLOAD_DELAY | Базовое значение 0,35 с; случайный множитель 0,5–1,5 по умолчанию |
| AutoThrottle | Включён; target=1, start=0,35 с, max=5 с; адаптация к времени ответа |
| DOWNLOAD_TIMEOUT | 20 с; ограничение ожидания отдельного запроса |
| RETRY_TIMES / HTTP_CODES | 2 повтора; 408, 429, 500, 502, 503, 504, 522, 524 |
| DEPTH_LIMIT | 12; хватает для десяти страниц списка и карточки; ограничивает обход |
| CLOSESPIDER_ITEMCOUNT / TIMEOUT | 300 цитат у quotes, 10 000 связей у tags; 900 с у обоих |
| HTTPCACHE_ENABLED | False для сетевых замеров; True в опытах кэша и JOBDIR |
| HTTPCACHE_EXPIRATION_SECS | 0; без истечения в изолированном учебном опыте |
| LOG_LEVEL | INFO; DEBUG для аудита запросов JOBDIR |

В `settings.py` даны комментарии к значениям. В колбэках нет блокирующего `time.sleep`. Для теста остановки лимит записей переопределён на 20; фактически завершилось 34 записи, потому что после начала закрытия были обработаны уже запущенные ответы.

## 6. JOBDIR и HTTP-кэш

| Прогон | Записи | Время, с | Cache store | Cache hit | Dupefilter |
|---|---:|---:|---:|---:|---:|
| cache_cold | 100 | 27,589 | 61 | 0 | 0 |
| cache_warm | 100 | 3,037 | 0 | 61 | 0 |
| job_pause | 34 | 0,593 | 0 | 23 | 0 |
| job_resume | 66 | 0,805 | 0 | 39 | 1 |

Два запуска кэша используют отдельные JOBDIR и одну директорию HTTP Cache: первый сохранил 61 ответ, второй прочитал 61 ответ без новых загрузок. Оба получили по 100 записей. Холодный прогон включает 10 списков, 50 авторов и проверку robots.txt. Сравнение относится к одному измерению на сохранённом наборе.

Остановка JOBDIR завершилась с `closespider_itemcount`. Содержимое состояния до продолжения сохранено в `data/jobstate_paused_listing.json`: очередь запросов, отпечатки `requests.seen`, `spider.state`. Повтор с тем же JOBDIR добавил 66 цитат; SQLite содержит 100 уникальных ключей. Стартовый URL был отфильтрован: `dupefilter/filtered=1`. В `data/job_audit.json` зафиксированы 22 посещённых URL до остановки и 38 после неё; пересечение равно нулю, robots.txt исключён. Это подтверждает отсутствие повторного обхода страниц, а не только наличие счётчика.

Возобновление проверено после штатного закрытия Scrapy; восстановление после повреждения файлов или внезапного отключения питания не проверялось. Очереди разных экспериментов разделены. Файлы `data/stats_*.json` сохраняются в `closed()` после закрытия пайплайна, поэтому учитывают последнюю неполную пачку SQLite.

## 8. Конвейер n8n

Manual start / Daily schedule → HTTP Request с пагинацией трёх страниц → HTML Extract → Split Out → подготовка контекста → Loop Over Items по одному → HTTP автора → HTML Extract → проверка полей → Wait 0,5 с → Remove Duplicates → Code с типизацией → CSV → Save CSV. Перед дедупликацией нормализуются пробелы в имени автора и тексте цитаты; окончательное приведение даты к ISO и тегов к нижнему регистру выполняется после неё. Невозможные календарные даты отклоняются, пустой массив тегов допустим. Расписание настроено на 08:00 Asia/Yekaterinburg; workflow оставлен неактивным, проверен ручной запуск.

В сетевых узлах задан Retry On Fail, максимум три попытки. Ошибки HTTP, структуры и типов записываются в `error_log.csv`; HTTP POST доставляет уведомление отдельному локальному приёмнику `127.0.0.1:5686`. Открытая панель браузера показывает сообщение и сохраняет `notifications.jsonl`. В тесте #9 приёмник подтвердил доставку кодом 201; при выключенном приёмнике тест #10 завершился сообщением `local notification FAILED`. Скриншоты ошибки и уведомления приложены. После ошибки прежний успешный CSV остаётся, поэтому требуется проверять статус последнего запуска.

Успешное выполнение n8n #8 получило 30 уникальных цитат со страниц 1–3 за 33,100 с; дата рождения, место и биография совпали со Scrapy. Экспорт — `nocode/workflow.json`, CSV — `nocode/nocode_result.csv`, показатели и ID — `metrics.json` и `execution_summary.json`. Скриншоты `screenshot_workflow.png`, `screenshot_execution.png`, `screenshot_history.png` сделаны в реальном интерфейсе. Искусственные сбои описаны в `error_test.json`; `validation_tests.json` содержит девять проверок кода узлов.

## 10. Выбор инструмента для трёх сценариев

Для разового обхода 500 страниц выберу Scrapy: уже реализованы пагинация, повторное использование карточек, проверяемый экспорт и контроль качества. При готовом простом API и существующем n8n-сценарии стоимость сборки могла бы изменить выбор; здесь измерена именно HTML-обработка.

Для ежедневных 40 000 страниц выберу Scrapy с постоянной БД, очередями заданий, журналами и мониторингом. JOBDIR помогает после штатной остановки, но не заменяет резервное копирование и управление распределённой очередью. Масштабирование не отменяет правила источника и ограничения нагрузки.

Для сбора со ста страниц и отправки отчёта в мессенджер выберу n8n при простой структуре источника: расписание, ветвление и интеграции собираются в одном workflow. Предлагаемый гибрид — n8n запускает Scrapy через Scrapyd/API, отслеживает статус, читает сводку качества и отправляет отчёт. В данной работе гибрид и отправка в мессенджер не реализованы.

## 11. Редизайн и smoke-check

Смена классов может дать пустые селекторы без HTTP-ошибки; новый формат даты — рост `dropped/invalid_value`; изменение пагинации — меньше страниц и записей. Проверяются структура карточки, обязательные поля, стабильный бизнес-ключ и итоговый объём. Индексные XPath не применяются. Теговый граф дополнительно может потерять связность: его покрытие сравнивается с полным каталогом, а не оценивается по числу переходов.

`quality/smoke_check.py previous.json current.json` выдаёт предупреждение и код 1 при падении числа записей более чем на 20% или доле пустых обязательных ячеек более 5%; ровно 20% и 5% проходят. Доля — число пустых обязательных ячеек, делённое на число таких ячеек во всех строках. Нули и пустые необязательные теги не являются пропусками. Несовместимые окна сбора и некорректные снимки дают код 2.

Сравнение независимых полных прогонов 100 → 100 завершилось без предупреждения. Проверки границ, 100 → 79, 5,01% пустот и пустого набора выполнены на синтетических примерах (`smoke_demonstration.json`); это не реальные сбои сайта. Умеренный рост DropItem при сохранении объёма может пройти этот порог, поэтому в статистике отдельно анализируются причины отброса. Сравнение с накопленной исторической таблицей вместо текущего прогона могло бы скрыть деградацию; для исходного снимка используется отдельная база холодного опыта.

## 12. Правовая и этическая оценка

Используется учебная площадка Quotes to Scrape; авторизация, обход капчи и антибот-защиты не применяются. Scrapy запрашивает robots.txt при `ROBOTSTXT_OBEY=True`; сервер вернул 404, опубликованных запретов в нём не получено. Проверка n8n дала тот же статус. Ответ 404 не является лицензией на произвольную обработку данных. Нагрузка ограничена параллелизмом, задержками, AutoThrottle, кэшем и предохранителями.

Имена, даты и места рождения и биографии относятся к сведениям о физических лицах. Публичная доступность не означает автоматического разрешения на любое использование или распространение; учебное назначение само по себе не отменяет требования 152-ФЗ. Данные хранятся локально для воспроизведения задания, контакты и сведения пользователей не собираются. Для использования вне учебного упражнения необходимо отдельно проверить основание обработки, цели, сроки хранения и права на тексты. Общедоступность страницы и соблюдение robots.txt решают разные вопросы.
