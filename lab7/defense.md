# Защита лабораторной 7

## Что сделано

**Мой вариант 3: HTML + API; 500 у одного источника, другой работает; 404 на отдельных URL.**
Работа про устойчивость HTTP-сборщика, а не про новый большой набор.
Профили A/B/C проверяются локально на одинаковых 60 архивных записях: 30 цитат и 30 книг.
Так можно воспроизвести сбой, не нагружая внешний сайт.

## 2. Показать ограничитель и повторы

Откройте src/limiter.py: token bucket, burst 1, два запроса/с на origin, jitter, адаптация.
Не путайте число воркеров с числом одновременных запросов на один домен.
Для каждого домена один владелец; файловая блокировка запрещает второму процессу одновременно забрать тот же домен.

В src/retry.py:
429, 5xx и сетевые ошибки можно повторять; обычные 4xx нельзя.
Retry-After важнее собственного backoff; поддерживаются секунды и HTTP-дата.
Максимум три попытки, бюджет восемь секунд на URL.
Если Retry-After не помещается в бюджет, URL прекращается, а не запрашивается раньше срока.

## 3. Сравнить A/B/C

~~~powershell
& $labPython -m src.collect --profile A
& $labPython -m src.collect --profile B
& $labPython -m src.collect --profile C
~~~

A - без ограничений, только локально.
B - с ограничителем и повторами, заполняет кэш.
C - плюс conditional GET, gzip и watermark.

Откройте reports/run_report_A.json, _B.json, _C.json.
Ожидаемые свойства (время плавает):

- Во всех результатах 60 записей.
- A/B: по десять запросов и 60 полученных по сети записей.
- Повторный C: четыре 304, шесть пропущенных страниц, ноль новых записей по сети.
- C возвращает 60 записей из проверенного архива, а не 60 новых загрузок.
- wire_bytes считает тела ответов. У 304 тело пустое, но HTTP-заголовки всё равно передаются.

В state/etags.json покажите ETag/Last-Modified; в watermark.json - версии ресурсов.
В reports/load_savings.json отдельно измерены conditional, gzip и incremental.
Для свежих графиков после команд повторно выполните ячейки analysis.ipynb.

## 4. Сбой одного источника и 404

Перед повтором сбойных сценариев перезапустите учебный сервер: Ctrl+C в первом окне и снова training_server.py.
Это сбросит счётчики намеренных ошибок.

~~~powershell
& $labPython -m src.collect --scenario faults
~~~

Откройте reports/scenario_faults.json:
initial_html_failed true, api_continues true, html_recovered true, final_breaker_state closed.
В указанном там JSONL-журнале найдите circuit_open, skip_open, circuit_half_open и circuit_closed.
Два 404 запрошены по одному разу; 429 проверен с Retry-After в секундах, датой и без него.

Фраза: «После двух 500 домен временно выключается. Другой источник работает. Затем делается один пробный запрос».
Красный статус здесь ожидаем: ошибки подготовлены специально.

## 7. n8n

Учебный сервер должен работать.
Откройте http://localhost:5679 и workflow лабораторной 7.
При необходимости импортируйте lab7/nocode/workflow.json и проверьте абсолютные пути Save CSV / Save error log.

1. Prepare requests: три страницы API.
2. Loop requests: по одной странице.
3. Wait: пауза 0,6 с.
4. HTTP Request: timeout, Retry On Fail для сетевых ошибок, полный HTTP-ответ.
5. Classify response: ограниченные повторы 429/5xx; 404 не повторяется.
6. Проверка числа строк и ветка ошибки → Stop and Error.
7. Execute workflow: три запроса и 30 строк, выходной CSV.
8. Daily schedule: расписание.

Покажите nocode/metrics_rate_limit.json: у подготовленного 429 четыре запроса вместо трёх.
nocode/metrics_missing_url.json: 404 отправлен один раз, workflow завершён ошибкой.
Это сохранённые отдельные проверки, обычный workflow сейчас должен пройти зелёным.

Нативного предохранителя с изоляцией доменов и conditional-кэша в этом workflow нет.
Ежедневный обычный запуск этого подмножества: 30 исполнений и 90 HTTP-запросов за 30 дней.
Локальный n8n и API без платы; оборудование и электричество отдельно не оценивались.
