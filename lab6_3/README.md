## Запуск Python

Нужен Python 3.10+. Откройте PowerShell в папке `lab6_3`:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m src.rebuild
.\.venv\Scripts\python.exe -m db.load --demonstrate
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Первый запуск заново строит `clean`, БД и `mart` из локальных файлов `raw`, без запросов к сайтам. При повторе исходные строки не переписываются, одинаковые записи БД не обновляются, партиции не накапливают дубли. Загрузка принимает **полный чистый снимок**: текущие записи отмечаются `is_active=1`, вытесненные остаются неактивными с сохранением истории. Она не предназначена для передачи произвольного частичного пакета как полного набора.

В [quality_report.ipynb](quality_report.ipynb) выберите созданное окружение и выполните ячейки сверху вниз. Сохранённые результаты уже включены. По умолчанию ноутбук читает файлы и проверяет пересборку в памяти, `RUN_REBUILD = True` включает перезапись производных файлов. Возраст данных считается при запуске: позднее архивный набор может получить жёлтый или красный статус по заданным порогам.

Проверка остановки при красном статусе:

```powershell
.\.venv\Scripts\python.exe -m src.rebuild --force-red
# Ожидается код завершения 2 и название красной метрики; mart не изменяется.
```

Три демонстрационные загрузки выполняются в отдельной временной БД, путь записан в `clean/idempotency.json`. В основной `db/warehouse.db` сохраняется исходный чистый набор. Демонстрация меняет теги только у двух записей: A — 420 вставок, B — 420 без изменений, C — 2 обновления, история 420 → 420 → 422. Результаты находятся в JSON и ноутбуке.

## Источники и учёт каждой строки

Использован сохранённый локальный архив: 100 цитат HTML Quotes to Scrape и 320 цитат API DummyJSON. HTML взят из снимка пятой работы, вместе с карточками и исходными значениями. DummyJSON был добавлен как отдельный учебный API, API третьей работы — Open Library. Этот источник не выдаётся за результат лабораторной № 3.

32 учебные дефектные копии помечены `_synthetic` и `_injected_reason` (7,08% входа). Они демонстрируют пропуски, дубли, битые даты, теги и невидимые пробелы. Итоговый баланс:

| Исходных строк | Принято | Отбраковано | Валидных дублей |
|---:|---:|---:|---:|
| 452 | 420 | 24 | 8 |

`clean/raw_disposition.json` назначает каждой входной строке ровно один итог. В `duplicates.jsonl` 14 альтернатив: 8 валидных дублей и 6 невалидных, которые одновременно отражены в rejects. Их нельзя повторно прибавлять к числу удалённых строк. В шести группах выбрана корректная старая запись вместо дефектной свежей.

Raw хранит URL, время UTC, имя источника, версию парсера и статус. SHA-256 в `raw/manifest.json` защищает прежний префикс от незаметного изменения, новые строки разрешены только дозаписью. Не редактируйте сырой слой для исправления clean: меняйте обработку и пересобирайте. Прикладная проверка хэша не заменяет права доступа и резервную копию. Настройка `.gitattributes` сохраняет исходные переводы строк при загрузке в Git и клонировании.

Ключ цитаты — SHA-256 строки `source + '|' + source_record_id` в UTF-8. Ведущие нули сохраняются. Изменение текста не меняет ключ, а совпадение ID из разных сервисов не создаёт коллизию. Почти-дубли группируются по нормализованным тексту и имени, одинаковые имена не доказывают тождество разных людей.

## n8n

Реальный прогон n8n 1.121.3 обработал 39 строк: 34 сохранены, 3 отбракованы, 2 дубля удалены. Повтор дал идентичные CSV. Снимки [схемы](nocode/screenshot_workflow.png) и [результата](nocode/screenshot_result.png) относятся к этой версии workflow. Данные совпадают с Python по ключу, тексту и автору.

Из папки этой лабораторной запустите соседний переносимый комплект (Python 3.10+ и Node.js 22 в PATH):

```powershell
python ..\n8n_portable\launch.py --setup --browser
python ..\n8n_portable\launch.py --port 5679
```

Первая команда устанавливает зависимости; при последующих запусках достаточно второй. Launcher задаёт рабочий каталог n8n равным корню комплекта `n8n_portable`, создаёт `outputs/lab3`–`outputs/lab7` и запускает локальные вспомогательные сервисы ЛР4 и ЛР5. Откройте `http://127.0.0.1:5679`, импортируйте `nocode/workflow.json` этой лабораторной или соответствующий `../n8n_portable/workflows/labN.json` и выполните **Manual start**. Все относительные пути файлов в workflow отсчитываются от корня комплекта, а не от папки лабораторной. При запуске n8n из другой директории без launcher нужно самостоятельно установить рабочий каталог и создать папки. Расписание в экспорте выключено.

Входной снимок входит в комплект: `../n8n_portable/labs/lab6_3/nocode/input.json`. Новые результаты находятся в `../n8n_portable/outputs/lab6/nocode_result.csv` и `outputs/lab6/rejects.csv`; журнал ошибки — `outputs/lab6/error_log.csv`. Workflow включает ежедневное расписание на 08:00 Asia/Yekaterinburg, но экспортирован неактивным.

Выбранная ветка n8n выполняет полный CSV-экспорт с заменой файла. **CSV не поддерживает построчный UPSERT.** Для него нужен узел PostgreSQL/MySQL и соединение с таблицей, в этом сценарии они не настроены. Ограничения и фактические результаты описаны в [nocode/notes.md](nocode/notes.md), а сопоставление с Python — в отчёте. Замена CSV не называется UPSERT.

## Вопросы по реализации

- **Почему JSONL для raw?** Он допускает дозапись по строкам и хранит исходные поля с происхождением.
- **Почему Parquet для clean?** Сохраняет UTC, nullable-числа, списки и строковый ID `000100`, можно читать выбранные столбцы.
- **Почему валидность 94,69%, а 420/452 — другое число?** Контракт прошли 428 строк до дедупликации, восемь валидных дублей исключены из clean.
- **Почему в протоколе 14 альтернатив, а валидных дублей восемь?** Шесть альтернатив не прошли контракт и учтены в браке, баланс проверяется по уникальному raw_index.
- **Почему не SCD2?** Для этого небольшого набора полные снимки изменившихся строк проще, C добавляет ровно две версии.
- **Как повтор распознаёт изменение?** Хэш payload, идентичный payload не меняет updated_at и не добавляет историю.
- **Что доказывает график дат?** Объём архивных наблюдений по дате сбора, включая помеченные учебные копии. Он не измеряет популярность цитат.
