# Запуск через n8n

Workflow запускает Python через локальный HTTP-обработчик. На вкладке Executions видны код возврата, число книг и путь к отчёту. Ошибку процесса или превышение порога показывает узел «Оповещение в n8n».

Python выдаёт предупреждение, если доля ошибок выше 15%, доля ответов `403/429` выше 5%, объём изменился больше чем на 15% относительно предыдущей загрузки или задержка p95 выше 2 000 мс. В сохранённом штатном повторе p95 составил 672 мс. Порог 2 000 мс оставляет запас на обычные колебания. При запуске без запросов p95 отсутствует. Ноль новых записей при повторе отмечается в отчёте как `info`.

В первом терминале из папки проекта запустите обработчик.

~~~powershell
.\.venv\Scripts\python.exe -m src.n8n_endpoint
~~~

Во втором терминале запустите локальный n8n. Проверено с n8n 1.121.3 и Node.js 22.

~~~powershell
$env:N8N_USER_FOLDER = (New-Item -ItemType Directory -Force .runtime/n8n).FullName
$env:N8N_HOST = 'localhost'
$env:N8N_PORT = '5687'
$env:N8N_LISTEN_ADDRESS = '127.0.0.1'
npx n8n@1.121.3 start
~~~

1. Откройте `http://localhost:5687`. В новом профиле создайте локального пользователя.
2. Откройте редактор и импортируйте `nocode/workflow.json` через Import from File.
3. Нажмите Execute workflow. Откройте «Показать отчёт о прогоне» и результат Python.
4. Для работы по расписанию включите сценарий в локальном n8n. В настройках workflow указан часовой пояс `Asia/Yekaterinburg`, время запуска 20:30.

Для демонстрации ошибки остановите обработчик клавишами Ctrl+C и запустите его с `--demo-failure`. Ручной запуск workflow покажет сбой. Для обычной работы перезапустите обработчик без флага.

| Этап | Python | n8n | Что остаётся в коде |
|---|---|---|---|
| Расписание и запуск | Команда CLI и локальный обработчик | Schedule Trigger и HTTP Request | Выполнение команды и код возврата |
| Запросы к источникам | Лимиты, `Retry-After`, очередь и кэш | Один запрос к обработчику | Пагинация, повторы, robots.txt |
| Очистка и загрузка | Контракты Pydantic, SQLite, Parquet | Читает итог запуска | Валидация, UPSERT, путь к данным |
| Контроль | Метрики, пороги, JSON-отчёт | IF, результат или Stop and Error | Расчёт метрик |

В штатном запуске срабатывают четыре узла n8n, включая один HTTP-запрос к локальному обработчику. За 30 суток получится около 30 исполнений и 120 срабатываний узлов. n8n работает локально, поэтому в этом запуске нет облачной тарификации. Запросы Python к сайтам учитываются отдельно.
